# 布局⇄布线 闭环协同自适应：快速板级模拟器与实验（PicoRick_One_revA）

代码：`parse_pcb.py`(解析) · `model.go sim.go`(栅格迷宫布线器) · `analysis.go`(失败分析/反事实) · `loop.go`(闭环) · `scenario.go`(收紧/间距) · `exp.go main.go paired.go`(实验) · `report.py plot.py`(表/图)。
复现：`python3 parse_pcb.py && go build -o coadapt . && ./coadapt exp -budget 75 && python3 report.py`；`./coadapt paired` 生成 paired_moves.json。
原始数据 `results/results.jsonl`(208 次)、`results_guided2.jsonl`(32 次)、完整表 `results/table.md`、等评估次数表 `results/equal_eval.md`、图 `results/*.png`。

## 1. 模拟器是什么、有多快
- 解析：145 个封装/500 焊盘（真实焊盘矩形/圆、旋转）、Edge.Cuts 外框 110x110.2 mm、4 层(F/In1/In2/B，In1/In2 为 GND 平面，GND 不布线)、.kicad_pro 网络类→线宽/间距（USB 0.28、Power3V3 0.4、Power5V/HV 0.6、PulseCurrent 0.5、Analog 0.25/0.2、Digital 0.15…），111 个可布线网络(248 个待连引脚)，原有走线忽略。
- 布线器：0.1 mm 栅格、F/B 两个信号层、8 邻域(45°)、A*(权重1.3、不重开节点)、过孔代价 1.5 mm、每个线宽/间距类一张占用图(双所有者槽)，树生长式多引脚布线；"封闭口袋"快速检测(有界泛洪)。
- 速度：整板布线 **约 1.0–2 s**（真实板 1101x1103 栅格，0.8 s–1.5 s；含失败网络），RRR 60 次约 +4–8 s；目标 <30 s 达成。闭环每次候选评估约 0.3–0.5 s（增量：只重布受影响网络 + 重建占用图）。
- 度量：未布通网络/引脚、总长度、过孔、"颈缩"长度(窄线段违反全宽的长度，作为违规成本而非门禁)、微孔数、拥塞热图(`dump` 输出)。
- **违规作为成本的两处放宽（务必知晓）**：(1) 引脚 1.2 mm 内走线收窄到 0.12 mm/间距 0.10 mm（"颈缩区"）；(2) 颈缩区内允许 0.3 mm 微孔(过孔进焊盘)，否则 0.4 mm 间距 QFN(U303) 无法扇出。标记 `strict` 的场景关闭微孔(只用 0.6 mm 过孔)，其 U303 扇出失败更多，是更接近"硬参数不过"的情形。

## 2. 发现的机理
1. 真实板在本模拟器里：class 顺序基线 5 引脚未布通(+60 次 RRR 后 4)；失败几乎全部是 **U303(RP2040 QFN-56)和 IC101 周围的引脚扇出被封死**（失败分析：口袋仅 16–130 个栅格，blame 落在 U303 自己的焊盘 + 紧邻去耦电容 C312/C313/C314/C315 + 其它网络刚好横穿出线口）。与"紧挨的器件把通道堵死"一致，且 `strict` 场景（无微孔）下 27→15 引脚未布通，说明 QFN 扇出主要是几何/过孔问题，不是间距缩放问题。
2. 把外框按 0.8/0.7/0.6 收紧并重新合法化(courtyard 不重叠)后，基线(class 顺序+RRR)未布通引脚 6.3 / 11.0 / 15.0（3 个种子均值），随板子变紧单调变差。
3. **路由侧的修复比挪器件更便宜、更有效**：
   - 网络顺序 `hpwl_asc`(短网络先布，其余仍保持"类内"无关)是最强的单一旋钮：real 5→**0**，pack0.8 12→0.7，pack0.7 15→3.7，real_strict 15→2；class 顺序(USB→电源→模拟→数字)并不最优。pack0.6 上 hpwl_asc 网络数少(8.3)但引脚 38(多引脚电源网整体掉线)，说明应作为"可轮换的顺序候选"而不是固定顺序。
   - `reverse`、`hpwl_desc` 多数更差。
4. 全局间距缩放(中心放大)：适度放松有帮助——1.15x：real 4→2，pack0.8 6.3→2.7，pack0.7 11→8.7(1.3x 为 6.3)；收紧 0.9x 变差(real 4→4，pack0.8→8.3，pack0.6 22)；1.5x 回头变差，且线长涨 30–40%。说明"稍松则可能通"成立但曲线是非单调的，最优值要靠评估，不能一刀切。
5. 闭环（引导：先 RRR 再单个被动件平移→簇→按 IC 侧非对称间距→IC，软惩罚而非锁定；含反事实归因）对比 `loop_rrr_only`(同样的 RRR 预算，不挪器件)：
   - real：2.0 → 1.0；pack0.8 4.7→3.7；pack0.7 10.7→6.3；pack0.6 14.3→9.3；real_strict 15→13；pack0.7_strict 22→18.5。**挪动确有增益**(相对"同样的重布但不挪")，平均接受 2–4 次挪动，位移均值 0.85 mm、最大 3.4 mm。
   - **但"失败引导"并不优于随机**：等评估次数表(equal_eval.md)里，引导在 E≤30 次评估时领先(pack0.7：E=10 为 8.7 vs 随机 10.0；E=30 为 7.7 vs 8.3)，而引导候选耗尽后很早停滞(pack0.7 约 20 次评估、pack0.6 约 70 次)，随机继续得到 E=120 时 pack0.7=2.7(引导 6.3)、real_strict 5.0(引导 13)、real 0.0(引导 1.0)。结论：当前归因给出的候选**排序略好、覆盖面更窄**；随机"撒点+严格接受"在预算充足时反而胜出，且接受的随机挪动多是远离 U303 的零件(R110、R306、R302 …)，更像"重布扰动/改变局部顺序"带来的收益而不是因果上的解堵。这是对"因果归因"设想的反面证据，必须如实说明。
   - 局部/整体间距膨胀候选(`loop_guided_spread`)在所有场景里**从未被接受**(结果与仅挪动逐项一致)；全局间距缩放(第 4 点)有效而局部单侧膨胀无效，提示膨胀要与重布整个 IC 周边一起做。
   - churn(被接受的挪动同时引出新的未布通网络)：引导 1.0–2.0 次/运行，随机 0.3–2.5；接受次数 2–10，所以约 25–60%，**高于评审建议的 25–30% 警戒线**，说明评估/接受规则仍未标定(接受条件目前只比较总未布通引脚数，未处理新增失败)。
   - 参考零位噪声：paired 实验里的 `control_noop`(几乎不动、仅触发相同的增量重布)使微孔场景的未布通从 2 变 4，其它单点挪动的预测增量全部在 ±2 引脚之内——**单次挪动的 ±2 以内变化不可信**，需要重复/固定顺序才能判定符号。

## 3. 闭环算法（已实现）
```
route_all(order)  [class | hpwl_asc | ...]
RRR(60)                                  # 重布：拆除封堵网络(<=2)，先布失败网
loop until budget or nothing left:
  target = 第一个未布通且未 stuck 的网络(按类优先级)
  blame  = Analyze(target)               # 两侧有界泛洪取较小的封闭口袋，边界格归属→器件/网络
  # (1) 仅路由修复(不挪器件)
  for k in 1..3: ripTry(target, 前k个封堵网络)      # 接受当且仅当总未布通引脚下降
  if 成功: continue
  # (2) 反事实：对 blame 前4个器件，临时"幽灵化"其铜后重试 target，relief=1(通)/0.5(少失败)
  cands = 被动件平移(8 方向 x {0.4,0.8,1.3,2.0,3.0}mm, 受限于位移上限与去耦半径)，被动件旋转90/180，
          [簇=无 / IC 软惩罚平移]，再加 IC 单侧间距膨胀(1.25,1.5)；按 tier→(away 余弦 + relief − 0.25·距离) 排序，取前K
  for c in cands:                         # 都从同一父状态出发
     apply(c) (合法性：courtyard 不新增重叠、出框、去耦帽距、MaxDisp)
     受影响网络 = 动到引脚的网 ∪ 铜穿过新旧 courtyard+1mm 的网 ∪ 10mm 内失败网
     拆除并按序重布(目标网优先)；accept 当 (未布通引脚↓) 或 (相等且 长度+4·过孔 降低>1%)
     否则整体回退(姿态+路由+占用图快照)
  无接受 → target 标 stuck；全部 stuck → K 加倍(<=24)，重来
```
未实现的评审建议（诚实说明）：最小割归属(用反事实+泛洪边界代替)、小束搜索/最佳 incumbent 单独存储(当前严格贪心单调，incumbent 即当前态)、拥塞溢出作第二比较项(只用未布通→长度+过孔)、PathFinder 历史代价。支撑/需求表见下。

## 4. IC 每侧"通道供给/需求"基线
`sideTable`(paired.go)：每侧在焊盘场外 1.2 mm 处扫线，扣除其它器件焊盘(+0.225)，供给=floor(自由长度/0.3)*2 层，需求=离开该侧的网络数 x1.2(USB x2)。U303 四侧供需比 2.3 / 2.4 / 3.6 / 2.9，**全部 ≥ 1.3**，即这个简单规则预测"不该失败"，而模拟里 strict 下 U303 仍有 15 个引脚失败(口袋被相邻线道/电容封死而非总宽度不足)——所以供需表**不是**有效预测量(至少需要考虑扇出过孔站位与出线口前方第一排器件距离)，列为待改进。

## 5. paired_moves.json（交给真实 fastroute 验证迁移）
28 个合法挪动，均相对**真实板原始摆放**：U303 邻近 5 个被动件径向 ±0.2/±0.5 mm(16)，3 个旋转180°，8 个 U303 单侧间距膨胀(1.15x/1.3x，涉及多器件)，1 个 control_noop。字段 `pred_unrouted`(微孔/严格两种设置下，从同一父状态增量重布后的未布通引脚，父状态分别为 2 与 18)、`pred_delta_pins`、`pred_churn_new_unrouted_nets`、`pred_supply_min_ratio_u303`。90° 旋转因 courtyard 重叠全部非法被过滤。建议在真实 fastroute 上固定顺序与种子重复 ≥3 次，先看 control_noop 的方差，再统计符号一致率。

## 6. 导出的最终挪动：nudges.json
真实板(scale 1.0、微孔)的最优闭环结果：随机 R110(+0.92,-0.92)、R306(-0.57,+0.57)、R302(+0.28,-0.28)、C316 旋转180°，未布通 4→0。引导闭环的最优为 C313(-0.92,-0.92)、U303(0,-0.8)、C315(-0.57,+0.57)，4→1。格式 (ref,dx,dy,rot) 相对原始摆放。**注意**：这些在模拟器里有效，但因噪声特性(见 2.5)，迁移到真实 fastroute 需要 paired_moves 的验证；而同一真实板仅用 `hpwl_asc` 顺序就 0 未布通，不挪任何器件。

## 7. 模拟器不能代表的东西
精确 DRC/0.1 mm 门禁(用颈缩 0.12/0.10 与微孔放宽；违规作为成本报告)；阻焊 0.127 mm 间距与阻焊桥；U303 散热焊盘与到平面的过孔(GND 视为平面，不布线，也未给 GND 焊盘预留过孔位)；热、电流承载铜面积(电源网按线宽走线而非铺铜)；USB 差分对耦合/等长(两条网按顺序独立布)；真实布线器的出线口策略与其 4 个失败网络未复现(本模拟器失败集中在 U303/IC101 扇出，真实板的 4 条失败原因是 0.4 mm 线宽，此处被颈缩放宽)；0.1 mm 栅格与焊盘中心的相位对齐；过孔位置与盲埋孔规则；两信号层(In1/In2 视为完整 GND 平面)。

## 8. 固化到 pcbpilot 的建议
- 入口：沿用 `pcb layout-plan`(产出摆放/意图) → `kicad route`(真实 fastroute)；新增一步 `coadapt`：输入 .kicad_pcb + intent，输出 `*.apply.json`(placement delta：[{ref,dx,dy,rot}])，由现有 placement apply 命令执行，再只对受影响网络调用 fastroute 的"局部重布"（受影响 = 动到引脚的网 + 铜穿过新旧 courtyard±1 mm 的网 + 10 mm 内失败网），不要整板重跑。
- 流程：fastroute 整板一次(取失败集) → 模拟器快速循环(秒级，先订单变体 hpwl_asc/类序轮换 + RRR，再挪动)，每批 top-3 候选用真实 fastroute 增量验证、失败回滚；模拟器仅作排序器。
- 度量门禁：最终交付仍走全部硬门禁；探索阶段颈缩/微孔仅作为成本。

## 9. 下一步实验（按价值排序）
1. 在真实 fastroute 上跑 paired_moves.json：看 control_noop 方差、预测符号一致率、churn；决定模拟器是否只做"顺序/RRR"而非挪动评估。
2. **顺序+闭环叠加**：在 hpwl_asc / 顺序轮换基础上再做引导与随机闭环（本次闭环都起于 class 顺序，而 hpwl_asc 单独就已解掉 real）。
3. 在相同评估次数下把引导候选做宽(簇平移、成对挪动、IC+其去耦帽联动)，并用反事实 relief 作为主排序而不是方向余弦，检验引导能否在 E≥100 追平随机。
4. 引入 PathFinder 历史代价与拥塞溢出作第二比较项，降低 churn；加入"最佳 incumbent"与小束搜索。
5. 局部间距膨胀与"出线口前第一排器件"的距离阈值(把 sideTable 改成基于出线口口袋面积)；做 QFN 扇出专用的预留线道/过孔站位。
6. 栅格 0.05/0.1/0.15 敏感性和焊盘相位扫描，量化颈缩/微孔假设对结论的影响；GND 焊盘过孔预留；USB 差分耦合。
