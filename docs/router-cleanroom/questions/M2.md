## Q6: neck-down for controlled-impedance and no-neck-down nets (decided in M2)

Spec 04 §3.5 forbids neck-down for controlled-impedance nets and for `intent.noNeckDown`; 01 §4 agrees.
M2 implements it as follows (see `pkg/pcbroute/rules/doc.go`):

- Intent flags: `rules.Intent.NoNeckDown` and `rules.Intent.ControlledImpedance`.
- From pcbpilot intent: `NoNeckDown` is set when `widthMil.min >= widthMil.outer` (tolerance 0.005 mil), the
  same test `internal/pcb/specctra` uses to list no-neck-down classes for the DSN path. A smaller
  `widthMil.min` becomes the net's `MinWidth`; nets without one use the narrowest `widthMil.min` of the board
  (else the fab minimum), as the DSN path does. `ControlledImpedance` is set for nets with an impedance target
  and for pcbauto's `diff` and `rf` roles.
- DSN mapping (for M3): no new keyword. A class whose nets may not neck down gets `MinWidth = Width` at its
  class scope; the resolver then returns `Neck.Zone = 0`.

Please record this in PLAN.md §5.2 Q6.

## Q-M2-1: inner-layer current width (spec 04 §4.2/§4.6 vs pcbauto)

Spec 04 sizes inner conductors with the IPC-2221 internal constant k = 0.024. pcbauto (`electrical.go`) sizes
inner widths with the external constant on the inner copper weight (its comment cites IPC-2152). M2 follows
the spec, so the v2 intent floor on inner layers is about 2.5x pcbauto's `InnerWidthMil` for power nets (bench:
146 of 7 980 checked values on the 7 fixtures differ, all inner widths, all explained by this floor; outer
widths and clearances match within 1 µm). Wider inner tracks only make the result stricter, but they push
power nets off inner signal layers. Should spec 04 keep k = 0.024, or adopt IPC-2152 for inner layers to match
pcbauto?
