# Skill 设计

`.agents/skills/pcbpilot/` 是唯一公开设计入口，CLI、daemon 和 Connector 为它服务。入口保持短小，
负责选择样例、说明参数入口、调用 typed 工具和安排独立验证；具体知识放在按需读取的参考与样例中。

源码仓库另有 `.agents/skills/pcbpilot-repo-lookup` 与 `pcbpilot-repo-maintain`，分别提供跨项目
查询与仓库维护，不拆分设计工作流、不随公开 Skill 发布。安装、文档归属与兼容入口见
[Agent 协作设计](agent-collaboration.md) 和 [文档索引](README.md)。

## 运行方式

Agent 按下列循环工作：

```text
选择相近样例 → 理解理由 → 替换参数 → 执行 → 读取实际结果 → 修正样例或实现
```

参数化源数据继续承担可重现性。原理图连接、模块归属和几何，PCB 的板框、器件位置与走线路径，
都应能从保存的输入重新计算。现场回读负责揭示宿主差异，不把旧 workflow stage、综合评分或版本状态
解释为执行许可。

## 短入口与按需读取

- `SKILL.md` 只保留工作循环、任务路由、不可省略的事实和验证状态定义。
- 样例索引连接具体功能例；原理图、PCB、选型和 API 参考按任务加载，避免每次读取完整手册。
- 完整日志、大图和开发历史留在开发资料中；安装包保留参数、可执行步骤、必要局部图与工具依赖。
- 公共样例使用现有 JSON、typed action、Cobra 子命令和 `pcbpilot apply`，不新建通用执行 DSL。

入口长度和首次阅读量用真实任务比较，目标约 60–90 行并减少约 60% 首次必要阅读；这些是优化目标，
不形成新的机械阻断条件。

## 样例契约

每个样例包含七类信息：

1. 解决的问题、适用场景和来源页码。
2. 开始状态，以及必须读取的新鲜对象。
3. 可修改参数、单位、坐标和 anchor 语义。
4. 实际执行过的命令或参数化脚本；未执行的步骤明确标出。
5. 完成后的数据回读和必要局部图。
6. 这样安排的理由、真实错误和修法。
7. 独立验证记录及尚未覆盖的部分。

共同做法共享样例，题目数值和例外放在各自参数中。没有完成态答案的题目先建草稿，现场复现并保存
重开核查后再升级为可照做的示范。

验证状态只使用：

| 状态 | 含义 |
|---|---|
| `source-only` | 只有题面、手册或规划依据，尚未执行。 |
| `offline-verified` | 数据、换算、命令签名或自动测试已离线核对。 |
| `live-verified` | 在真实 EasyEDA 文档执行，并完成 save → reload → readback。 |

文档修改、源码存在和离线测试都不能单独标记 `live-verified`。

## 检查与验证者

连接、NC、DRC、几何、规则和评分分别输出具体对象与差异。缺测、刷新失败和未保存记为
`incomplete`。检查结果用于修正，不组成阶段签字或 subagent 放行链。

独立验证有三种方式：

- 步骤核查：验证者只收到原题要求和实际结果，报告差异、证据和修法。
- 独立照做：新验证者仅使用打包 Skill、原始材料和工具执行指定步骤，检验样例是否自包含。
- 迁移测试：调整自由参数、板尺寸或线宽，验证规则与题目例外没有被写死。

主 Agent 控制现场写入。subagent 可并行做资料分析、离线计算和只读检查；需要编辑器写入时使用独立
页面并串行访问。错误实例用于检验检查覆盖，发现问题直接修复样例或实现。

## 维护要求

改变底层命令、采集或算法时，同步相应样例、工具说明和覆盖边界。缺失 typed 能力时先查
CLI help、action 和官方 API；可重复操作沉淀为 typed action 与 Cobra 子命令。

修改 Skill 后运行 frontmatter/link 检查和 `python3 scripts/pack-skill.py --check`。这些检查只证明
包结构和依赖完整；算法回归、现场复现和历史题迁移分别保留自己的证据。
